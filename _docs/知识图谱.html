    📖 小白词典

    JWT（门禁卡）
    登录成功后后端发给你的一串加密字符串，之后每次请求都带着它，后端一看就知道「你是谁、有什么权限」。本项目里 24 小时过期。
    HMAC 签名（防伪章）
    通信双方约定一把密钥，发送方把参数排序拼接后用密钥算出「指纹」一起发过去；接收方用同一把密钥重算一遍，对得上才受理——防止有人伪造请求。
    异步回调（留电话等通知）
    你下单后不用一直等着，支付网关处理完后会「主动打电话」给酒店后端（服务器对服务器发 POST），告知支付结果。
    幂等（按多少次电梯都只来一趟）
    同一个通知重复送达很多次，业务后果和送达一次完全相同。本项目的回调接口对已终态的支付单直接回复成功并忽略。
    补偿查询（等不到通知就主动去问）
    万一回调在网络里丢了，后端会周期性地拿着支付单号去网关查询真实状态，把账补上——两条路保证最终一致。
    反向代理（前台总机）
    Nginx 站在所有服务前面，对外只有一个端口；外部请求先到它，再由它按路径分发给后面的内部服务。后端因此不必暴露在公网。
    ORM（用 Python 对象操作表）
    SQLAlchemy 让你写 Booking.status = "checked_in" 这样的 Python 代码，它自动翻译成 SQL 去读写数据库，不用手拼 SQL 字符串。
    外键（表之间的亲属关系）
    一张表里存另一张表的主键（如 bookings.customer_id 存 users.id），用来表示「这单预订属于哪个顾客」。
    多态关联（biz_type + biz_id）
    支付单可能指向「预订」也可能指向「账单」，用 biz_type 说明挂靠的是哪种业务、biz_id 说明是哪一条。
    状态机（人生轨迹图）
    对象在几个固定状态之间跳转，每次跳转都由明确的操作触发、且要满足校验条件。本项目的房间、预订、支付都有清晰的状态机。
    原路退款（从哪来回哪去）
    退款退回当初支付的渠道（支付宝付的退支付宝）。取消已支付预订时，后端会调用网关的退款接口模拟这一过程。
    种子数据（开箱即用的演示数据）
    首次启动时自动写入的演示内容：4 种房型、20 间客房、3 个演示账号、近 7 天的历史账单等，保证一打开就有东西可看。
